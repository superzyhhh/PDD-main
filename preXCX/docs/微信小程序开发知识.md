## 1. 框架总览：双线程模型

来源：[MINA 框架介绍](https://developers.weixin.qq.com/miniprogram/dev/framework/MINA.html)、[逻辑层介绍](https://developers.weixin.qq.com/miniprogram/dev/framework/app-service/)、[视图层介绍](https://developers.weixin.qq.com/miniprogram/dev/framework/view/)

- 整个框架系统分为**逻辑层（App Service）**与**视图层（View）**两部分：逻辑层运行在独立的 JavaScript 引擎中，视图层用 WXML/WXSS 描述页面结构样式，两层之间由框架提供的数据传输和事件系统连接（官方文档中即所谓 JSBridge 通道；官方页面表述为「数据传输和事件系统」）。
- 数据绑定是两层之间的核心：逻辑层只改数据（`setData`），视图层自动更新；视图层的用户事件回传给逻辑层的事件处理函数。
- 逻辑层**并非运行在浏览器中**，因此没有 `window`、`document` 等 Web 能力（官方明确提示）。
- 一句话版：**渲染层（WebView 等渲染引擎，每页独立环境）负责 WXML/WXSS 渲染；逻辑层（单线程 JS 引擎，所有页面共享）负责数据与业务；两层通过数据/事件通道通信。** 原生组件（如 camera、map 等）由客户端原生渲染并叠加在 WebView 之上；「同层渲染」是让这类原生组件与普通元素在同一图层渲染、可被正常遮罩/变换的技术（细节以官方组件文档为准：https://developers.weixin.qq.com/miniprogram/dev/component/ ）。
- 框架还维护页面路由与完整生命周期，并提供丰富原生 API。

## 2. 目录结构与全局配置

来源：[目录结构](https://developers.weixin.qq.com/miniprogram/dev/framework/structure.html)、[小程序配置](https://developers.weixin.qq.com/miniprogram/dev/framework/config.html)、[全局配置参考](https://developers.weixin.qq.com/miniprogram/dev/reference/configuration/app)

### 2.1 工程文件清单

一个小程序主体由三个文件组成，必须放在项目根目录：

| 文件 | 必需 | 作用 |
|---|---|---|
| app.js | 是 | 小程序逻辑 |
| app.json | 是 | 小程序公共配置 |
| app.wxss | 否 | 小程序公共样式表 |

每个页面（和自定义组件）由四个文件组成，且**必须具有相同的路径与文件名**：

| 文件 | 必需 | 作用 |
|---|---|---|
| .js | 是 | 页面逻辑 |
| .wxml | 是 | 页面结构 |
| .json | 否 | 页面配置 |
| .wxss | 否 | 页面样式表 |

允许上传的资源白名单（后缀）：`wxs / png / jpg / jpeg / gif / svg / json / cer / cert / mp3 / aac / m4a / mp4 / wav / ogg / silk / wasm / br`。其余文件在工具里可见但无法上传。

### 2.2 app.json 关键字段

官方「小程序配置」页给出的常用结构：

```json
{
  "pages": ["pages/index/index", "pages/logs/logs"],
  "window": { "navigationBarTitleText": "Demo" },
  "tabBar": {
    "list": [
      { "pagePath": "pages/index/index", "text": "首页" },
      { "pagePath": "pages/logs/logs", "text": "日志" }
    ]
  },
  "networkTimeout": { "request": 10000, "downloadFile": 10000 },
  "debug": true
}
```

| 字段 | 作用 | 文档要点 |
|---|---|---|
| pages | 页面路径列表 | 第一项为首页；新页面路径必须有对应 .json/.wxml/.js 文件（js 需注册页面） |
| window | 全局窗口表现 | navigationBarTitleText、navigationBarBackgroundColor、navigationBarTextStyle、backgroundColor、backgroundTextStyle 等，可被页面配置覆盖 |
| tabBar | 底部标签栏 | list 的 pagePath 必须是主包页面；tabBar 页面必须在主包内（分包文档规定） |
| networkTimeout | 网络超时 | 如 request/downloadFile 单位 ms；网络默认超时 60s（网络能力文档） |
| debug | 调试开关 | 开启后可在控制台查看调试信息 |
| permission | 权限说明 | 需授权 scope.userLocation 等时必须配置「地理位置用途说明」（授权文档） |
| requiredPrivateInfos | 声明隐私位置接口 | 用于声明 getLocation 等隐私接口（完整字段以全局配置参考为准） |
| subPackages（或 subpackages） | 分包结构 | 见第 7 节 |
| preloadRule | 分包预下载 | 见第 7 节 |
| lazyCodeLoading | 按需注入 | `"requiredComponents"`，见第 8 节 |
| initialRenderingCache | 初始渲染缓存 | 放在 window 段，`"static"`/`"dynamic"`/`"capture"`，见第 8 节 |
| restartStrategy | 重新启动策略 | `homePage`（默认）/`homePageAndLatestPage`（不可用于 tab 页） |
| darkmode / usingComponents / sitemapLocation 等 | 其他 | 完整字段列表以[全局配置参考](https://developers.weixin.qq.com/miniprogram/dev/reference/configuration/app)为准 |

### 2.3 页面 .json 与全局配置的关系

- 每个页面可用同名 `.json` 对本页窗口表现做配置，**页面配置项会覆盖 `app.json` 的 `window` 中相同配置项**（官方原话）。
- 页面常用字段：`navigationBarBackgroundColor`、`navigationBarTextStyle`、`navigationBarTitleText`、`backgroundColor`、`backgroundTextStyle`；另有 `restartStrategy`、`initialRenderingCache`、`handleWebviewPreload` 等页面级配置（见性能章节）。完整列表以[页面配置参考](https://developers.weixin.qq.com/miniprogram/dev/reference/configuration/page)为准。

## 3. 逻辑层：App / Page / setData / 路由 / 模块化

来源：[逻辑层介绍](https://developers.weixin.qq.com/miniprogram/dev/framework/app-service/)、[注册小程序](https://developers.weixin.qq.com/miniprogram/dev/framework/app-service/app.html)、[注册页面](https://developers.weixin.qq.com/miniprogram/dev/framework/app-service/page.html)、[API 调用约定](https://developers.weixin.qq.com/miniprogram/dev/framework/app-service/api.html)、[页面路由](https://developers.weixin.qq.com/miniprogram/dev/framework/app-service/route.html)、[运行机制](https://developers.weixin.qq.com/miniprogram/dev/framework/runtime/operating-mechanism.html)

### 3.1 App 注册

每个小程序都要在 `app.js` 里调用 `App()` 注册实例，绑定生命周期回调、错误监听、页面不存在监听等。**整个小程序只有一个 App 实例，全部页面共享**；页面里用 `getApp()` 获取。

```js
// app.js
App({
  onLaunch(options) { /* 冷启动时执行一次 */ },
  onShow(options)  { /* 前台/启动 */ },
  onHide()         { /* 切后台 */ },
  onError(msg)     { console.log(msg) },
  globalData: 'I am global data',
})
```

```js
// 页面里取全局数据
const appInstance = getApp()
console.log(appInstance.globalData)
```

### 3.2 App / Page 生命周期表

小程序运行机制（[官方](https://developers.weixin.qq.com/miniprogram/dev/framework/runtime/operating-mechanism.html)）：切后台约 5 秒后 JS 线程停止（挂起，内存保留）；挂起约 30 分钟未回前台或资源紧张会被销毁。

| App 生命周期 | 触发时机 |
|---|---|
| onLaunch | 小程序初始化完成，全局触发一次 |
| onShow | 启动或从后台进入前台 |
| onHide | 从前台进入后台 |
| onError | 脚本错误或 API 调用报错 |
| onPageNotFound | 打开的页面不存在（文档说明见 App 参考） |

| Page 生命周期 | 触发时机 |
|---|---|
| onLoad | 页面加载，一个页面只调一次；参数 options 携带路径 query |
| onShow | 页面显示/重新显示（页面切换回栈顶、前台） |
| onReady | 页面初次渲染完成（官方定义的「首页渲染完成」即首个页面 onReady） |
| onHide | 页面隐藏（navigateTo/switchTab 离开时触发，不销毁） |
| onUnload | 页面销毁（redirectTo/navigateBack/reLaunch） |
| onSaveExitState | 小程序可能被销毁前调用，可返回 `{ data, expireTimeStamp }` 保存退出状态 |

**路由切换时组件与页面生命周期的触发顺序**（页面路由文档）：

- 页面创建：组件 `created` → 组件 `attached` → 组件 `pageLifetimes.show` → `Page.onLoad` → `Page.onShow`
- 页面销毁：组件 `beforeDetach` → 组件 `detached` → `Page.onUnload`
- 页面隐藏：组件 `pageLifetimes.hide` → `Page.onHide`
- 页面展示：组件 `pageLifetimes.show` → `Page.onShow`
- 注意：`onShow` 也会在页面重新可见时触发，别把一次性初始化逻辑写在里面。

### 3.3 Page 注册与 setData

```js
Page({
  data: { text: 'Initial data' },
  onLoad(options) { /* 页面创建时执行，options 为路径参数 */ },
  viewTap() { this.setData({ text: 'Updated data' }) },
})
```

官方复杂页面建议改用 `Component` 构造器注册页面（见第 4.4 节）。

**setData 正确用法与性能红线**（来源：[合理使用 setData](https://developers.weixin.qq.com/miniprogram/dev/framework/performance/tips/runtime_setData.html)）：

1. 影响性能的两因素：组件 Shadow 树总节点量、单次更新数据量；**前者影响更大**。
2. 频率红线：**避免毫秒级高频调用 setData**——会让逻辑层 JS 线程持续繁忙、通信耗时上升、渲染延迟、滑动卡顿；❌ 避免在页面滚动回调中每次都 setData；❌ 避免页面切后台后仍高频更新（如倒计时）。
3. 批量：用「组合更新」把连续 setData 尽量合并；❌ 不要 `this.setData(this.data)` 一次性传所有 data；✅ 只传发生变化的字段。
4. 路径更新：可以按数据路径精确更新，如 `this.setData({ 'A[0].B': 'myPrivateData' })`（Component 构造器文档示例）。
5. data 只放渲染相关数据：渲染无关数据挂在 `this.userData = {...}` 等非 data 字段；渲染间接相关可用纯数据字段（[pure-data](https://developers.weixin.qq.com/miniprogram/dev/framework/pure-data)）+ observers 监听；❌ 不要用 data 做页面/方法间数据共享。
6. 无法避免的频繁更新（倒计时类）：封装成独立小组件缩小 Shadow 树、可用 CSS contain 限制绘制范围。
7. 分析：用 `setUpdatePerformanceListener` 获取更新性能统计。

### 3.4 页面路由 API 对照表

页面栈上限：`getCurrentPages` 可反映页面栈；路由由页面栈+悬垂页面组织（tabBar 页面处于栈中时必为栈底，且同一 tab 页最多一个实例）。连续路由会排队依次执行，路由确定后不可取消。

| API | 栈行为 | 目标限制 | 生命周期 |
|---|---|---|---|
| wx.navigateTo | 打开新页面并推入栈 | **目标必须为非 tabBar 页面** | 原栈顶 onHide，新页面 onLoad/onShow |
| wx.redirectTo | 栈顶页面被替换销毁 | 目标必须为非 tabBar 页面 | 原页面 onUnload，新页面 onLoad/onShow |
| wx.navigateBack | 弹出栈顶若干页销毁 | 页面栈只剩一个页面时调用失败 | 被弹页面 onUnload |
| wx.switchTab | 关闭所有非 tab 页，切到目标 tab 页 | **目标必须为 tabBar 页面** | 原 tab 页 onHide；目标页 onShow 或创建 |
| wx.reLaunch | 销毁所有页面后打开目标页 | 任意页面（含 tabBar、首页） | 所有页面 onUnload，目标页创建；**不重启 AppService，全局状态不重置** |

传参：`url` 里带 query，如 `/pages/detail/detail?id=1&from=share`，目标页 `onLoad(options)` 的 `options.id/options.from` 接收。页面间还可用 EventChannel 通信（navigateTo 文档）；跳转前可提前为下一页发数据请求，减少用户等待。

```js
wx.navigateTo({ url: '/pages/detail/detail?id=1' }) // 打开新页面
wx.navigateBack({ delta: 1 })                        // 返回上一页
wx.redirectTo({ url: '/pages/other/other' })         // 关闭当前页并跳转
wx.switchTab({ url: '/pages/index/index' })          // 切到 tab 页
```

### 3.5 模块化 require

逻辑层提供模块化能力，**每个页面有独立的作用域**。模块用 CommonJS 风格的 `module.exports` 导出、`require()` 引入（官方小程序文档表述；WXS 之外不支持 ES6 import 的默认行为以工具编译文档为准）。

```js
// utils/api.js
function request(options) { /* ... */ }
module.exports = { request }
```

```js
// pages/index/index.js
const api = require('../../utils/api')
```

注意：分包之间不能 require（见第 7 节引用原则）。

## 4. 自定义组件

来源：[自定义组件介绍](https://developers.weixin.qq.com/miniprogram/dev/framework/custom-component/)、[Component 构造器](https://developers.weixin.qq.com/miniprogram/dev/framework/custom-component/component.html)、[组件模板和样式](https://developers.weixin.qq.com/miniprogram/dev/framework/custom-component/wxml-wxss.html)、[Behaviors](https://developers.weixin.qq.com/miniprogram/dev/framework/custom-component/behaviors.html)（抓取失败处以介绍页行为描述为准）

### 4.1 Component 骨架

组件同样由 json/wxml/wxss/js 四文件组成；组件的 `.json` 必须声明 `"component": true`。使用方在页面（或 app.json 全局）用 `usingComponents` 声明标签名与路径。官方 Component 构造器骨架：

```js
Component({
  behaviors: [],
  properties: {
    myProperty: { type: String, value: '' },  // 属性名
    myProperty2: String                        // 简化定义
  },
  data: {},                                    // 私有数据，用于模板渲染
  lifetimes: {                                 // 组件生命周期
    attached() {}, moved() {}, detached() {},
  },
  pageLifetimes: {                             // 组件所在页面的生命周期
    show() {}, hide() {}, resize() {},
  },
  methods: {
    onMyButtonTap() { this.setData({ /* 更新属性和数据 */ }) },
    _myPrivateMethod() { this.setData({ 'A[0].B': 'myPrivateData' }) }, // 内部方法建议下划线开头
  },
})
```

```json
// pages/index/index.json —— 声明引用
{ "usingComponents": { "component-tag-name": "path/to/the/custom/component" } }
```

注意事项（官方）：标签名只能小写字母/中划线/下划线；项目根目录名不能以 `wx-` 开头；组件 wxss 中**不应使用 ID 选择器、属性选择器和标签名选择器**；使用 `usingComponents` 后页面 `this` 原型会有差异（多出 `selectComponent` 等方法，setData 不再直接深复制）。

### 4.2 properties / observers

- `properties` 是组件外部可传入的属性：`{ type, value, observer }`；属性值与 `data` 一样参与组件 WXML 渲染。使用时 `<component-tag-name prop-a="{{dataFieldA}}">`（组件模板和样式文档）。
- 属性变化监听可用字段级 `observer` 或组件级 `observers` 定义段；observers 可监听 properties/data 任意字段（含数据路径），官方组件框架文档描述：`observers: { 'numberA, numberB': function(a, b) {...} }`。observers 细节以[组件框架-数据监听器](https://developers.weixin.qq.com/miniprogram/dev/framework/component-framework/observer)为准。

### 4.3 slot 与 triggerEvent 通信

- 组件模板中提供 `<slot>` 节点承载引用方插入的子节点；启用 `options: { multipleSlots: true }` 后可用多个具名 slot：

```html
<!-- 组件模板 -->
<view class="wrapper">
  <slot name="before"></slot>
  <view>这里是组件的内部细节</view>
  <slot name="after"></slot>
</view>
```

```html
<!-- 引用方 -->
<component-tag-name>
  <view slot="before">插入 slot name="before"</view>
  <view slot="after">插入 slot name="after"</view>
</component-tag-name>
```

- 子 → 父通信：在组件方法里 `this.triggerEvent('myevent', { detail 数据 }, { bubbles/composed })`，引用方用 `bindmyevent` 监听（组件事件官方说明：https://developers.weixin.qq.com/miniprogram/dev/framework/custom-component/events.html ）。传值则通过 properties 向下、triggerEvent 事件向上。

### 4.4 Behaviors 复用 & Component 构造页面

- `Behavior()` 用于把公用的数据、属性、方法、生命周期提取成可复用段，多个组件/页面通过 `behaviors: [myBehavior]` 引用；组件间同名字段按官方合并规则处理（合并规则以 Behaviors 文档为准）。
- **页面也可以用 `Component` 构造器构造**：要求对应 json 含 `usingComponents` 定义段；页面参数会赋给同名 properties（如访问 `?paramA=123&paramB=xyz` 时声明 `properties: { paramA: Number, paramB: String }`）；页面生命周期（on 开头的方法）要写在 `methods` 段中。好处是可以用 behaviors 提取所有页面公用代码（如创建/销毁时的埋点日志）。

## 5. 视图层：WXML / WXSS / WXS

来源：[视图层介绍](https://developers.weixin.qq.com/miniprogram/dev/framework/view/)、[WXML](https://developers.weixin.qq.com/miniprogram/dev/framework/view/wxml/)、[WXSS](https://developers.weixin.qq.com/miniprogram/dev/framework/view/wxss.html)

### 5.1 WXML 语法速查

| 语法 | 写法 | 说明 |
|---|---|---|
| 数据绑定 | `<view>{{message}}</view>` | data 字段渲染到节点 |
| 列表渲染 | `<view wx:for="{{array}}">{{item}}</view>` | 默认下标变量 `index`、项变量 `item`，可用 `wx:for-item`/`wx:for-index` 改名；建议配 `wx:key` |
| 条件渲染 | `wx:if / wx:elif / wx:else` | 值为真才渲染；也可用 `hidden` 控制显隐（区别见 WXML 参考） |
| 模板 template | `<template name="staffName">…</template>` + `<template is="staffName" data="{{...staffA}}">` | 一次性定义、多处使用；`{{...obj}}` 展开传参 |
| 引用 | `<import src="a.wxml"/>`、`<include src="b.wxml"/>` | import 引入 target 的 template（有作用域）；include 复制除 template/wxs 外的整段代码（细节以 WXML 语法参考为准） |
| 事件 | `bindtap="handler"`（catch 阻止冒泡） | 事件系统文档：https://developers.weixin.qq.com/miniprogram/dev/framework/view/wxml/event |

```html
<!-- 模板示例（官方） -->
<template name="staffName">
  <view>FirstName: {{firstName}}, LastName: {{lastName}}</view>
</template>
<template is="staffName" data="{{...staffA}}"></template>
```

### 5.2 WXSS 与 rpx

- WXSS 具有 CSS 大部分特性；选择器例外：**属性名选择器 `[...]` 不生效**、不支持带参数的伪类/伪元素；最佳实践是**只推荐用 class 选择器**。
- 样式导入：`@import "common.wxss";`；全局样式：`app.wxss` 作用于所有页面（页面可配置禁止生效）；最佳实践是 app.wxss 只放绝大多数页面必须的样式，其余用 @import。
- 内联样式 `style="..."` 只在需要数据绑定时使用（如 `style="color: {{color}};"`），不建议放长样式。
- **rpx 换算**：rpx 表达页面总宽度的 1/750。页面宽度 375px 时，`1rpx = 0.5px`（即 750rpx = 屏宽）。官方提示：rpx 计算会对转换值取整带来精度问题，可开启 `convertRpxToVw` 选项规避；因 CSS 标准的 vw 已广泛支持，**官方优先推荐 vw**（1vw = 页宽 1%，375px 屏时 1vw=3.75px）。同时官方不建议滥用 vw/rpx 这类屏宽比例单位，大屏设备需配合 Media Query 等响应式布局。
- 渲染引擎影响：默认 WebView 引擎下样式兼容受各 OS WebView 影响；Skyline 引擎另有 WXSS 限制（见官方 Skyline 说明）。

### 5.3 WXS 是什么 / 何时用

- WXML 页面介绍明确：**WXS（WeiXin Script）是辅助 WXML 使用的简单脚本**，写在 `<wxs>` 标签或 `.wxs` 文件里，可被 WXML 直接调用做数据格式化/简单计算，减少「逻辑层 → 视图层」的通信。
- WXS 在视图层运行，不能调用逻辑层 API（如 wx.*），也不能调用组件方法；语法接近 JS 子集（运行环境不同，与 JS 是隔离的；模块用 `module.exports` 导出、`<wxs src>`/`module` 引用）。
- 何时用：频繁渲染中重复出现的格式化（时间、标签文本）、滚动/触摸事件里需要高频处理的纯函数。
- ⚠️ WXS 语法参考页本次抓取失败，完整语法以官方为准：https://developers.weixin.qq.com/miniprogram/dev/reference/wxml/wxs.html

## 6. 常用 API 速查（按本项目高频场景组织）

来源：[API 调用约定](https://developers.weixin.qq.com/miniprogram/dev/framework/app-service/api.html)、[网络使用说明](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html)、各 API 单页（链接随条目给出）

API 三种形态（官方）：`on` 开头=事件监听 API；`Sync` 结尾=同步 API（出错抛异常，需 try/catch）；其余为异步 API（success/fail/complete 回调）。基础库 2.10.2 起，参数不含 success/fail/complete 时异步 API 默认返回 Promise；但 `request/downloadFile/uploadFile/connectSocket/createCamera` 因本身有返回值，promisify 需自行封装。

### 6.1 网络请求

来源：[wx.request](https://developers.weixin.qq.com/miniprogram/dev/api/network/request/wx.request.html)、[网络使用说明](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html)、[wx.uploadFile](https://developers.weixin.qq.com/miniprogram/dev/api/network/upload/wx.uploadFile.html)、[wx.downloadFile](https://developers.weixin.qq.com/miniprogram/dev/api/network/download/wx.downloadFile.html)

**域名与 HTTPS 硬性要求**：
- 小程序只能与**配置过的服务器域名**通信（request/uploadFile/downloadFile/connectSocket 四类）；域名只支持 `https`/`wss`，不能是 IP 或 localhost，必须 ICP 备案，不支持配置父域名；`api.weixin.qq.com` 不能配置为服务器域名。
- 后台配置路径：「小程序后台-开发-开发设置-服务器域名」。配置端口后只能请求该端口；不配置端口则请求 URL 也不能带端口（443 也不行）。
- **必须 HTTPS/WSS**，证书要求：系统信任、域名一致、有效期内、信任链完整；iOS 不支持自签名证书、需满足 ATS；TLS 必须 1.2 及以上。
- 开发期可在工具勾选「不校验合法域名」跳过，但上线前务必关闭并真机验证。

**并发与超时**：
- `wx.request`/`wx.uploadFile`/`wx.downloadFile` 最大并发 **10** 个；`wx.connectSocket` 最大 **5** 个。
- 默认超时 **60s**，可在 app.json `networkTimeout` 配置，也可调用时传 `timeout`（ms，优先级更高，如 `wx.request({ timeout: 5000 })`）。
- 小程序切后台 5s 内网络请求未结束会报 `fail interrupted`，回前台前无法再发起请求。
- `wx.request` 参数要点：`url`（必填）、`data`、`header`（content-type 默认 `application/json`；**不能设置 Referer**）、`method`（默认 GET，合法值 OPTIONS/GET/HEAD/POST/PUT/DELETE/TRACE/CONNECT）、`dataType`（默认 `json`，会 JSON.parse；其他值不解析）、`responseType`（默认 text，可 arraybuffer）、`timeout`（默认 60000，基础库 2.10.0）。
- **只要成功收到服务器返回，无论 statusCode 是多少都会进 success 回调**，业务需自行判断状态码（官方红线）。建议服务端返回 UTF-8。

```js
wx.request({
  url: 'https://api.example.com/endpoint',
  method: 'POST',
  data: { code },
  header: { 'content-type': 'application/json' },
  timeout: 5000,
  success(res) { if (res.statusCode === 200) { /* 业务判断 */ } },
})
```

```js
wx.downloadFile({
  url: 'https://api.example.com/export.png',
  header: { 'x-session-token': token },
  success(res) { if (res.statusCode === 200) { /* res.tempFilePath */ } },
})
```

### 6.2 登录（wx.login → code2session）

来源：[小程序登录](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/login.html)、[wx.login](https://developers.weixin.qq.com/miniprogram/dev/api/open-api/login/wx.login.html)

官方时序（5 步）：
1. 小程序端调用 `wx.login()` 获取**临时登录凭证 code**；
2. code 回传开发者服务器；
3. 服务器调用 `auth.code2Session`（服务端接口）换取**用户唯一标识 OpenID**、微信开放平台下的** UnionID**（若已绑定开放平台账号）与**会话密钥 session_key**；
4. 服务器据用户标识生成**自定义登录态**（如 token）；
5. 后续业务前后端交互携带该登录态识别用户身份。

红线（官方注意事项）：**session_key 不应下发到小程序、也不应对外提供**；**临时 code 只能使用一次**。

```js
wx.login({
  success(res) { console.log(res.code) }, // res.code 传给自己服务器换 openid
})
```

### 6.3 存储

来源：[wx.setStorageSync](https://developers.weixin.qq.com/miniprogram/dev/api/storage/wx.setStorageSync.html)、[wx.getStorageInfoSync](https://developers.weixin.qq.com/miniprogram/dev/api/storage/wx.getStorageInfoSync.html)、[存储策略](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/storage.html)

| API | 要点 |
|---|---|
| wx.setStorageSync(key, data) | 同步写入指定 key，覆盖旧值；**单个 key 最大 1MB，所有数据上限 10MB**；只支持原生类型、Date、可 JSON.stringify 的对象 |
| wx.getStorageSync(key) | 同步读取，key 不存在返回空字符串 |
| wx.removeStorageSync(key) / wx.clearStorageSync() | 删除 |
| wx.getStorageInfoSync() | 返回 keys / currentSize(KB) / limitSize(KB) |

- 数据除非用户主动删除或系统因空间清理，否则一直可用。
- **官方红线：storage 只用于持久化存储，不应用于运行时数据传递或全局状态管理；启动期过多同步读写会显著影响启动耗时**。全局状态用 `App.globalData`。

```js
try { wx.setStorageSync('key', 'value') } catch (e) {}
try {
  const res = wx.getStorageInfoSync()
  console.log(res.currentSize, res.limitSize)
} catch (e) {}
```

### 6.4 图片与相册（本项目导出图纸的核心链路）

来源：[wx.chooseMedia](https://developers.weixin.qq.com/miniprogram/dev/api/media/video/wx.chooseMedia.html)、[wx.saveImageToPhotosAlbum](https://developers.weixin.qq.com/miniprogram/dev/api/media/image/wx.saveImageToPhotosAlbum.html)、[授权](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/authorize.html)

**wx.chooseMedia**（基础库 2.10.0 起支持；`wx.chooseImage` 自 2.21.0 起停止维护，请改用 chooseMedia）：
- 功能：拍摄或从相册选择图片/视频。关键参数：`count`（默认 9，2.25.0 起最多 20）、`mediaType`（默认 `['image','video']`，可选 image/video/mix）、`sourceType`（默认 `['album','camera']`）、`sizeType`（默认 `['original','compressed']`）、`maxDuration`（默认 10，3–60s）、`camera`（默认 'back'）。
- success 返回 `res.tempFiles[].tempFilePath / size / duration / width / height / fileType`、`res.type`。
- **chooseMedia 属隐私接口**（「收集你选中的照片或视频信息」），需在隐私指引中声明并完成用户同意（见第 10 节）。

```js
wx.chooseMedia({
  count: 1,
  mediaType: ['image'],
  sourceType: ['album', 'camera'],
  success(res) { console.log(res.tempFiles[0].tempFilePath) },
})
```

**wx.saveImageToPhotosAlbum**（基础库 1.2.0 起）：
- 功能：保存图片到系统相册；参数 `filePath` 必填——**可以是临时文件路径或永久本地路径，不支持网络路径**（下载/画布导出的 tempFilePath 可直接传）。
- **用户授权：需要 `scope.writePhotosAlbum`**。授权规则：未处理过会弹窗；已拒绝过则**不再弹窗、直接 fail**——必须兼容拒绝场景：fail 里引导 `wx.openSetting` 打开设置页让用户手动开启。

```js
wx.saveImageToPhotosAlbum({
  filePath: tempFilePath,
  success() { wx.showToast({ title: '已保存到相册', icon: 'none' }) },
  fail() { // 用户拒绝过授权 → 引导去设置页开启
    wx.showModal({ title: '需要相册权限', content: '请在设置中开启「添加到相册」权限',
      success(res) { if (res.confirm) wx.openSetting() } })
  },
})
```

相关：`wx.openDocument` 打开文档（本项目用于打开分块打印图）；`wx.setClipboardData` 复制文本；`wx.getFileSystemManager().readFile` 读取本地临时文件（FileSystemManager 细节以官方为准：https://developers.weixin.qq.com/miniprogram/dev/api/file/wx.getFileSystemManager.html ）；`wx.editImage` 图片裁剪编辑（接口细节以官方为准：https://developers.weixin.qq.com/miniprogram/dev/api/media/image/wx.editImage.html ）。

### 6.5 分享

- 页面内转发：定义 `Page.onShareAppMessage(res)` 后右上角菜单可转发；给 `button` 设 `open-type="share"` 也能触发。
- 返回值（Page 参考）：`{ title, path, imageUrl }` 等；**不自定义转发图片时，默认截取当前页面从顶部开始、高度为 80% 屏幕宽度的图像**作为转发图。

```js
  },

```

### 6.6 Canvas 2d 要点（本项目画图纸的核心链路）

来源：[Canvas 对象](https://developers.weixin.qq.com/miniprogram/dev/api/canvas/Canvas.html)、[WXML 节点信息 SelectorQuery](https://developers.weixin.qq.com/miniprogram/dev/api/wxml/SelectorQuery.html)

- 页面写 `<canvas type="2d" id="xxx">`，通过 `wx.createSelectorQuery().select('#xxx').fields({ node: true, size: true }).exec(cb)` 拿到 **Canvas 节点 node**（不是 2d 旧接口的 context）。Canvas 实例属性：`width/height`；方法：`getContext('2d')`、`createImage()`、`createImageData()`、`createPath2D()`、`requestAnimationFrame()`、`cancelAnimationFrame()`、`toDataURL()`。
- **dpr 处理**：用 `wx.getWindowInfo().pixelRatio` 取设备像素比；画布物理尺寸 = 逻辑尺寸 × dpr，再 `ctx.scale(dpr, dpr)` 用逻辑坐标绘制，保证导出清晰。
- 拿到 node 后 `node.getContext('2d')` 的 2d 上下文用法与标准 Canvas API 一致；图片用 `canvas.createImage()` 创建（而非 Image 构造器）。
- 导出图片：canvas 2d 节点可配合 `wx.canvasToTempFilePath({ canvas })`（新接口传 canvas 而非 canvasId），或 `Canvas.toDataURL()`；保存相册用 6.4 的 saveImageToPhotosAlbum。

```js
wx.createSelectorQuery()
  .select('#pattern')
  .fields({ node: true, size: true })
  .exec((result) => {
    const node = result[0] && result[0].node
    if (!node) return
    const dpr = wx.getWindowInfo().pixelRatio
    node.width = size * dpr
    node.height = size * dpr
    const ctx = node.getContext('2d')
    ctx.scale(dpr, dpr)
    // 之后按逻辑坐标绘制
  })
```

## 7. 分包加载

来源：[分包加载](https://developers.weixin.qq.com/miniprogram/dev/framework/subpackages.html)、[使用分包](https://developers.weixin.qq.com/miniprogram/dev/framework/subpackages/basic.html)、[分包预下载](https://developers.weixin.qq.com/miniprogram/dev/framework/subpackages/preload.html)

### 7.1 大小限制（官方数字）

- 整个小程序所有分包大小不超过 **30M**（服务商代开发的小程序不超过 20M）；
- **单个分包/主包大小不能超过 2M**；
- 启动时默认只下载主包并启动主包内页面；用户进入分包页面时才下载对应分包。
- 主包放置：默认启动页面 / tabBar 页面、所有分包都要用的公共资源与 JS。

### 7.2 subPackages 配置示例

```json
{
  "pages": ["pages/index"],
  "subPackages": [
    { "root": "packageA", "pages": ["pages/cat", "pages/dog"], "entry": "index.js" },
    { "root": "packageB", "name": "pack2", "pages": ["pages/apple", "pages/banana"] }
  ]
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| root | String | 分包根目录 |
| name | String | 分包别名，分包预下载时可用 |
| pages | StringArray | 分包页面路径，相对分包根目录 |
| independent | Boolean | 是否独立分包 |
| entry | String | 分包入口 JS 文件（注入时首先执行） |

**打包原则**：声明 subPackages 后按配置路径打包，配置外目录进主包；主包可有最外层 pages；**subPackages 根目录不能是另一个 subPackages 的子目录；tabBar 页面必须在主包内**。

**引用原则**：packageA 不能 require packageB 的 JS（分包异步化时不受限）；不能 import packageB 的 template；不能使用 packageB 的资源；主包与自身包内资源可用。

### 7.3 preloadRule 分包预下载（基础库 2.3.0+）

```json
{
  "preloadRule": {
    "pages/index": { "network": "all", "packages": ["important"] },
    "sub1/index": { "packages": ["hello", "sub3"] },
    "indep/index": { "packages": ["__APP__"] }
  }
}
```

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| packages | StringArray | 是 | 无 | 进入页面后预下载的分包 root 或 name；`__APP__` 表示主包 |
| network | String | 否 | **wifi** | `all` 不限网络 / `wifi` 仅 wifi 下预下载 |

限制：**同一分包中的页面享有共同的预下载大小限额 2M**（工具打包时校验）；预下载只支持配置方式，不支持 API 调用；vConsole 里 `preloadSubpackages` 开头日志可验证。

## 8. 性能优化清单

来源：[启动性能](https://developers.weixin.qq.com/miniprogram/dev/framework/performance/tips/start.html)、[代码包体积优化](https://developers.weixin.qq.com/miniprogram/dev/framework/performance/tips/start_optimizeA.html)、[代码注入优化](https://developers.weixin.qq.com/miniprogram/dev/framework/performance/tips/start_optimizeB.html)、[首屏渲染优化](https://developers.weixin.qq.com/miniprogram/dev/framework/performance/tips/start_optimizeC.html)、[合理使用 setData](https://developers.weixin.qq.com/miniprogram/dev/framework/performance/tips/runtime_setData.html)、[页面切换优化](https://developers.weixin.qq.com/miniprogram/dev/framework/performance/tips/runtime_nav.html)、[初始渲染缓存](https://developers.weixin.qq.com/miniprogram/dev/framework/view/initial-rendering-cache.html)

官方建议启动耗时参考值：安卓需要下载/更新时 3.7s（本地代码包 2.6s），iOS 1.8s（0.9s）。「启动」指冷启动，从用户打开到**首页 onReady**。

### 8.1 启动性能

1. **分包加载**（效果最明显）：按使用频率拆分包，减小首屏下载与注入体积；独立分包可脱离主包运行（适合广告页/活动页）。
2. **代码包瘦身**：避免非必要的全局自定义组件和插件（全局 usingComponents 会随主包注入）；图片/音视频等资源尽量放 CDN、避免 base64 内联过大图片；及时清理无用代码与资源（用工具「代码静态依赖分析」）。
3. **按需注入 lazyCodeLoading**（基础库 2.11.1+）：app.json 配 `"lazyCodeLoading": "requiredComponents"`，只注入当前访问页面所需代码。注意：页面 JSON 声明的组件与 app.json 全局组件仍会被注入；要及时移除未使用的组件声明，避免全局声明低频组件。配合「用时注入」（为组件配置占位组件）可进一步延迟注入到首次渲染时。
4. **启动期少调同步 API**：onLaunch/onShow/onLoad 等生命周期里避免同步 API（`Sync` 结尾及 getSystemInfo）；`getSystemInfoSync` 应缓存、启动期最多一次；`getStorageSync/setStorageSync` 只用于持久化，别拿来传状态。避免启动期复杂运算。
5. **初始渲染缓存**（基础库 2.11.1+，仅 WebView 渲染引擎）：非首次启动时视图层不等逻辑层初始化完成，直接用上次页面初始 data 的渲染结果提前展示。页面 json 配 `"initialRenderingCache": "static"`；动态内容用 `"dynamic"` + `this.setInitialRenderingCache(dynamicData)`（不能早于 onReady 调用；`"capture"` 自定义缓存时机，基础库 3.7.4+）。缓存阶段仅支持 view/text/button/image/scroll-view/rich-text 等内置组件。
6. **首屏渲染**：精简首屏 data（渲染无关数据不放 data）；首屏数据请求提前到 onLoad 或更早（数据预拉取/周期性更新可进一步提前）；先从 storage 缓存渲染、网络回来再更新；骨架屏（工具可生成）。
7. **页面切换**：onHide/onUnload 里避免耗时操作（同步 API、setData），必要时 setTimeout 延迟；跳转分包页前可提前发起下一页请求。

### 8.2 setData 优化（详见 3.3 节）

要点回顾：控制频率（❌ 毫秒级、❌ 滚动回调里、❌ 后台态页面高频更新）；合并批量（❌ setData(this.data)）；按路径精准更新；data 只放渲染相关数据；频繁更新封装成小组件；用 `setUpdatePerformanceListener` 定位瓶颈。

### 8.3 长列表 / 渲染

- 官方运行时性能文档给出的渲染优化入口：[渲染性能优化](https://developers.weixin.qq.com/miniprogram/dev/framework/performance/tips/runtime_render.html)。长列表的核心思路（依据 setData 文档推导）：合理拆分组件控制 Shadow 树大小、分页/分片 setData 更新、列表项用纯数据字段减少传输量。

## 10. 隐私与合规

来源：[小程序隐私协议开发指南](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/PrivacyAuthorize.html)、[用户隐私保护指引填写说明](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/)、[小程序用户隐私保护指引内容介绍](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/miniprogram-intro.html)、[授权](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/authorize.html)

### 10.1 用户隐私保护指引

- 涉及处理用户个人信息的小程序，均需在后台填写《小程序用户隐私保护指引》（入口：「账号设置-服务内容声明-用户隐私保护指引」或提审时在「版本管理-提交代码审核」页填写）。**只有指引中声明过的信息，才可调用对应接口/组件；未声明则接口直接禁用**（报错 errno 112：`fail api scope is not declared in the privacy agreement`）。
- 隐私接口与信息对照（摘录与本项目相关项）：

| 处理的信息 | 接口或组件 |
|---|---|
| 收集你选中的照片或视频信息 | wx.chooseImage、wx.chooseMedia、wx.chooseVideo |
| 使用你的相册（仅写入）权限 | wx.authorize({scope:'scope.writePhotosAlbum'})、wx.saveImageToPhotosAlbum、wx.saveVideoToPhotosAlbum |
| 收集你的昵称、头像 | button open-type="chooseAvatar"、input type="nickname"（wx.getUserProfile 等已回收） |
| 读取你的剪切板 | wx.setClipboardData、wx.getClipboardData |

- **图片上传类目注意点**：本项目将用户选中的图片上传到自建服务器生成图纸，属于「收集你选中的照片或视频信息」，隐私指引必须如实声明该用途；平台会对处理目的审核。`wx.chooseMedia` 调用受隐私弹窗约束（见 10.2）。图片服务器域名需 https + ICP 备案（见 6.1）。

### 10.2 隐私接口与授权流程（基础库 2.32.3+）

- 2023-10-17 之后隐私相关功能强制启用（无需再配 `__usePrivacyCheck__`）。
- 开发方式三选一/组合：
  1. **主动查询**：`wx.getPrivacySetting` 查 `needAuthorization`；需要时展示自研弹窗 + `<button open-type="agreePrivacyAuthorization" bindagreeprivacyauthorization="...">` 同意按钮；`wx.openPrivacyContract` 打开协议全文。
  2. **被动监听**：`wx.onNeedPrivacyAuthorization(resolve => {...})`，用户触发未同意的隐私接口时回调；同意后调 `resolve({ event: 'agree', buttonId: 'agree-btn' })`。
  3. **辅助接口**：`wx.requirePrivacyAuthorize` 在真实隐私接口调用前「模拟」一次调用以触发弹窗逻辑。
- 不适配时会兜底：微信弹出**官方隐私弹窗**（拒绝后 10 秒内重复调用不再弹窗、直接报错，错误码 103/104）。

```js
wx.getPrivacySetting({ // needAuthorization 为 true 时展示隐私弹窗 + agreePrivacyAuthorization 按钮
  success(res) { if (res.needAuthorization) this.setData({ showPrivacy: true }) },
})
```

### 10.3 授权（scope）要点

- 授权机制：未处理过 → 弹窗询问；已授权 → 直接可用；**已拒绝 → 不弹窗直接 fail，必须兼容**。授权记录保存到用户删除小程序为止。
- 与本项目相关 scope：`scope.writePhotosAlbum`（saveImageToPhotosAlbum）；`scope.camera`（camera 组件）；`scope.userLocation` 等（如需）。
- 前置 API：`wx.getSetting` 查当前授权状态；`wx.openSetting` 打开设置页引导开启；`wx.authorize` 提前发起授权。
- 最佳实践（官方）：**在真正需要使用授权接口时才发起申请**，并说明使用理由。
