# Domain Docs

工程技能在勘察代码前，如何消费本仓库的领域文档。

## 勘察前先读

- **`CONTEXT.md`**（位于 `.agents/`），或
- **`CONTEXT-MAP.md`**（若存在）：它指向每个上下文各自的 `CONTEXT.md`，只读与当前主题相关的那些。
- **`docs/adr/`**：读与将要改动区域相关的 ADR。

若这些文件不存在，**静默继续**。不要提示缺失，也不要主动建议先创建。`domain-modeling` 技能只在术语或决策真正落定时才惰性创建它们。

## 文件结构

单上下文仓库（本仓库）：

```
.agents/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-....md
│   └── 0002-....md
└── .scratch/
    └── <feature-slug>/
        ├── spec.md
        └── issues/
            └── NN-<slug>.md
```

## 使用术语表中的词汇

输出中出现领域概念时（工单标题、重构提案、假设、测试名），使用 `CONTEXT.md` 定义的词，不要漂移到它标注为 _Avoid_ 的同义词。

若需要的概念尚未入表，这是一个信号：要么你在发明项目不用的语言（重新考虑），要么确实存在缺口（记下来交给 `domain-modeling`）。

## 显式指出 ADR 冲突

若输出与既有 ADR 冲突，必须显式指出，不要静默覆盖：

> _与 ADR-0007（事件溯源订单）冲突，但值得重开，因为……_
