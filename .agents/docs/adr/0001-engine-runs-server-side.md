# 引擎在服务端运行，小程序端不复用 GPL 代码

Pindo-main 以 `GPL-3.0-only` 发布，其 `lib/engine` 正是「智能抠图—自动减色—色号校准」的核心资产，重写代价过高。我们把该引擎原样部署在自有服务端容器中，微信小程序端从零实现，代码包内不含任何 GPL 覆盖代码。理由：小程序代码包会被下发到用户设备，构成 GPL 意义上的分发；而 GPL-3.0 不是 AGPL，纯服务端运行不触发分发义务。若将来把该服务端组件对外分发，则以 GPL-3.0 公开其源码。

**Consequences：** 出图改为异步（上传 → 云端精算 → 回传）；小程序端需重做渲染、导出与全部交互；需要承担服务器与带宽成本。经勘察，引擎内仅图片加载与图案识别两个模块依赖浏览器对象，其余可在 Node 直接运行，此方案可行性成立。

**Considered Options：** 端侧复用并整体以 GPL-3.0 开源（放弃闭源与差异化护城河）；净室重写（成本最高，且引擎正是要做深的部分）。
