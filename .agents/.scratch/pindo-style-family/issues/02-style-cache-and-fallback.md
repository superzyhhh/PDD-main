# 02 — 风格缓存与失败降级

**What to build:** 同一张原图、同一种风格只调用一次风格服务；只改成品尺寸档、色卡档或高级设置时复用已风格化图片，不重复调用；换风格必重新风格化并重新出图。风格服务超时、报错或返回坏图时，任务以「风格化失败」结束，玩家可以一键跳过风格、按原图继续生成，不需要重新上传或重选图片。

**Blocked by:** 01

**Status:** ready-for-human

- [x] 同图同风格重复提交复用结果，不重复调用风格服务
- [x] 仅改成品尺寸档、色卡档或高级设置时，复用已风格化的图片，不重复调用风格服务
- [x] 换风格必产生新图纸，不命中旧风格的结果
- [x] 风格服务超时、非成功响应或返回不可解码图片时，任务以「风格化失败」结束且不产出候选
- [x] 风格化失败后，玩家可一键跳过风格、按原图继续生成，无需重新上传或重选图片
- [x] 假风格服务可稳定模拟成功、超时、错误响应、坏图四种情况
- [x] 自动化测试通过调用记录断言缓存命中与换风格重算，并覆盖四种失败情况的用户可见结果

## Comments

- 风格图缓存位于服务端，键为「原图内容 + 风格标识 + 模型/提示词版本」；版本字段由风格适配层提供，替换模型或提示词即自然失效旧缓存。缓存有上限，按先进先出淘汰。
- 同一张原图同一种风格的并发请求会合并成一次风格服务调用；失败结果不写入缓存，重试会重新调用。
- 风格服务调用统一套上超时与取消：默认超时由适配层配置，超时、非成功响应、返回坏图都映射为「风格化失败」，任务不产出候选。
- 图纸内容寻址已含风格，换风格一定产生新任务；只改成品尺寸档、色卡档或高级设置时命中任务复用或复用已风格化图片。
- 客户端在风格化失败的错误态提供「跳过风格，按原图生成」，复用内存中的已选图片直接重试；「重试」保持原风格。
- 假风格服务支持 `success`、`timeout`、`error`、`bad-image` 四种稳定行为，仅用于本地演示与自动化测试。
- 验证：`npm run ci` 全绿（11 个测试文件、80 个用例）；风格 seam 测试 21 个，其中缓存与失败降级 11 个。
- 未覆盖：风格缓存命中率等运行指标留在验证期观察；看板与失败样本的风格维度属工单 03。
