# 01 — 风格族选择与风格服务骨架

**What to build:** 玩家在生成页可以选风格族（原图、动漫风、Q版、像素风、写实风、线条风），默认原图。选非原图时，服务端先通过可替换的风格服务把原图转成风格图，再走既有出图流水线，仍然返回三张候选；预览页回传并展示本次风格，非原图带「AI 风格化」标识。没有配置风格服务时，原图生成与现网完全一致，风格选项不出现。

**Blocked by:** None — can start immediately

**Status:** ready-for-human

- [x] 生成页出现风格族选择，默认原图；风格服务不可用时整组隐藏
- [x] 风格随生成请求提交并被服务端校验；非法值返回可识别的参数错误，缺省按原图处理
- [x] 启用假风格服务时，非原图风格先生成风格图再出图；仍恰好三候选，成品尺寸档、色卡档与色号规则不变
- [x] 任务结果回传本次实际风格；预览页展示风格，非原图展示「AI 风格化」标识
- [x] 风格图输出再次经过内容安全校验，命中时任务以可识别的不合规原因结束并提示换图
- [x] 未配置风格服务时，原图生成、复用与失败行为与现网一致，选择风格返回明确的不可用提示
- [x] 自动化测试覆盖默认原图、非法风格、非原图出三候选、任务结果回传风格、输出被拦截

## Comments

- 风格适配层位于服务端，提供未配置（关闭）与确定性假实现两种；小程序端不持有任何厂商 SDK 或密钥。
- 本地演示或联调时可设 `STYLE_SANDBOX=1` 启用假实现；生产环境启动会拒绝该配置，避免生产流量误用假服务。
- 风格图在抠主体之前生成，风格服务拿到的是解码并摆正后的 PNG；风格输出再次过内容安全，命中以 `style-blocked` 结束，风格服务异常或坏图以 `style-failed` 结束。
- 图纸内容寻址已包含风格：换风格一定产生新任务，避免命中旧风格结果；同一风格重复生成仍走既有复用。
- 权益接口下发 `styles.available` 与 `styles.options`（含原图与五种风格）；客户端据此渲染并隐藏不可用入口。任务结果同时回传风格标识与展示文案，「我的图纸」重新打开时尽量沿用；任务已被淘汰时退回不展示。
- 两级风格缓存、跳过风格与超时重试、看板按风格拆分分别留给工单 02、03。
- 验证：`npm run ci` 全绿（11 个测试文件、68 个用例），新增风格 seam 测试 9 个。
