# 03 — 风格维度看板与失败样本

**What to build:** 运营者可以在既有时间与渠道过滤下，按风格看到生成任务数、生成用户数、首图接受数与接受率，以及风格化失败次数与失败率；失败样本记录、列表与 CSV 导出都带风格字段，便于按风格定向分析。

**Blocked by:** 01

**Status:** ready-for-human

- [x] 看板汇总在时间与渠道过滤下，按风格给出生成任务数、生成用户数与首图接受数、接受率
- [x] 看板按风格给出风格化失败次数与失败率，同一任务只计一次
- [x] 失败样本记录、后台列表与 CSV 导出包含风格字段，既有列与时间过滤保持不变
- [x] 风格维度不改变原有生成到付费漏斗、7 日二次生成与盲测统计口径
- [x] 自动化测试覆盖按风格拆分、失败计数去重、CSV 含风格列，以及时间与渠道过滤叠加

## Comments

**实现要点**

- 看板汇总新增按风格拆分：六种风格各给出生成任务数、生成用户数、首图接受数与接受率，以及风格化失败次数与失败率；拆分叠加在既有时间与渠道过滤之上，原有汇总、漏斗、7 日二次生成与盲测口径不变。
- 风格化失败按任务去重，只计「风格化失败」这一种原因；「风格化内容不合规」是独立失败原因，不计入失败次数与失败率，避免把内容审核拦截误读为供应商不稳定。失败率分母为该风格成功生成任务数加风格化失败数，无任何尝试时返回空值。
- 风格信息由服务端在生成完成与首图接受时从任务元数据派生，客户端无需新增字段；失败样本留档、后台列表与 CSV 导出追加风格列，CSV 风格列放在既有列之后，时间过滤与引号转义保持不变。
- 看板接口返回结构新增按风格数组，既有字段保持原样，便于既有后台继续读取。

**验证**

- 自动化测试覆盖：按风格拆分与时间、渠道同时生效；风格化失败次数与失败率及同一任务去重；风格化内容不合规不混入失败口径；失败样本列表带风格；CSV 表头与行尾风格列、既有列与时间过滤不变。
- 完整 CI（类型检查、GPL 边界扫描、全量测试）通过。

**未覆盖项**

- 未做真机冒烟：风格维度只影响后台取数，界面无新增入口，真机回归归工单 12。
- 风格服务仍为假实现，按风格的失败率在接入真实厂商后需要重新基线化。
