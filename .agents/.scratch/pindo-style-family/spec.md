# 拼豆图纸生成小程序 · 风格族规格

## Problem Statement

零经验玩家手里多是照片或截图，现有主流程只能把原图忠实转成图纸，无法得到动漫风、Q 版这类效果。想要风格化就得先用别的工具转换，再导回来生成，来回折腾；而这类工具往往带水印、按次收费，转出来的图也不保证能拼。

对运营者来说，风格族是第 2 迭代的付费与留存抓手，但如果没有按风格分开的生成量、接受率与失败率，就无法判断哪种风格值得继续投入。

本轮要解决的是：玩家在上传后可以直接选一个风格族并拿到可拼图纸；没有厂商账号时也能先把整条链路、界面与数据准备好；真实厂商接入时不改动主链路。

## Solution

主流程增加一个可选的风格族选择，默认「原图」。选择其他风格后，服务端先用可替换的风格服务把原图转成风格图，再走既有的抠主体、降采样、色号匹配与三候选流水线。成品尺寸档、色卡档、三候选、导出与材料清单的规则全部不变。

风格服务通过可注入的适配层接入：本轮提供确定性的假实现，真实厂商的账号与密钥到位后只替换适配层，不动生成、缓存、界面与看板。风格图与最终图纸分别缓存，避免重复调用；风格服务失败时用户可一键跳过风格继续出图。看板与失败样本增加风格维度，供验证期按风格取数。

## User Stories

1. 作为玩家，我想在生成前选择风格族（原图、动漫风、Q 版、像素风、写实风、线条风），这样我能拿到想要的效果。
2. 作为不想折腾的玩家，我想默认就是原图，这样我不选风格也能照常出图。
3. 作为玩家，我想一次选择就应用到同批三张候选，这样我不用逐张做风格化。
4. 作为玩家，我想风格化后仍然拿到三张候选（保主体细节、保色彩层次、保少色号），这样我还能按自己的偏好挑一张。
5. 作为玩家，我想在预览页看到本次实际使用的风格，这样我能确认没有选错。
6. 作为玩家，我想在风格化结果上看到「AI 风格化」标识，这样我知道这张图经过了生成式处理。
7. 作为玩家，我想在风格服务失败时一键跳过风格、按原图继续生成，这样我不会白等一次。
8. 作为玩家，我想在风格服务超时或异常时看到可重试的提示，这样我知道不是图片本身的问题。
9. 作为玩家，我想在风格化结果不合规时被告知换图，这样我知道下一步该做什么。
10. 作为玩家，我想同一张图、同一风格重复生成时直接复用结果，这样我不浪费等待时间。
11. 作为玩家，我想只改成品尺寸档、色卡档或高级设置时不重新做风格化，这样出图更快。
12. 作为玩家，我想换风格时一定重新出图，这样我不会拿到旧风格的结果。
13. 作为玩家，我想在当前环境不支持风格化时看不到风格选项，这样我不会点到一个必然失败的按钮。
14. 作为玩家，我想风格化后的图纸仍然严格落在所选色卡档，这样我买豆不会超出套装。
15. 作为玩家，我想风格化不改变成品尺寸档与拼板数，这样我准备的底板数量不变。
16. 作为运营者，我想按风格看到生成任务数、生成用户数与首图接受率，这样我知道哪种风格值得继续投入。
17. 作为运营者，我想按风格看到风格化失败次数与失败率，这样我能发现供应商稳定性或提示词问题。
18. 作为运营者，我想失败样本带上风格字段并可按时间导出，这样我能定向分析某一种风格的问题。
19. 作为运营者，我想风格维度叠加在时间与渠道过滤之上，这样我能按投放渠道评估不同风格的效果。
20. 作为开发者，我想用一个可替换的风格服务接口与假实现，这样没有厂商账号也能开发、演示和自动化测试。
21. 作为开发者，我想风格服务配置缺失时系统行为与上线前完全一致，这样部署不会因为少一个配置而不可用。
22. 作为合规负责人，我想用户原图在送往第三方风格服务前有明确告知，输入与输出都经过内容安全检查，这样上传内容不会被无感知外传。

## Implementation Decisions

**术语与范围**

- 使用「风格族」统称六种选择：原图、动漫风、Q 版、像素风、写实风、线条风；「原图」表示不做风格化。
- 风格只作用于生成前的图片，不改变「图纸」「候选」「成品尺寸档」「色卡档」「材料包」的任何既有定义。

**风格服务适配层**

- 服务端新增可注入的风格服务适配层，与内容安全、支付渠道一样由部署配置决定实现；小程序端不包含任何厂商 SDK 或密钥。
- 适配层契约：输入原图与风格标识，输出一张可解码的风格图与内容类型；必须支持超时与取消，返回的图片必须落在服务端既有的像素上限内。
- 本轮提供两种实现：未配置（等同于关闭）与确定性的假实现。真实厂商适配器在账号与密钥到位后新增，不修改主链路。
- 配置项至少包含：风格服务开关、服务地址、密钥、超时时间、模型/提示词版本。模型或提示词版本参与缓存键，版本变化必须让旧风格缓存失效。

**请求与任务契约**

- 生成请求新增风格标识，取值固定为六种；缺省为原图，非法值返回可识别的参数错误。未配置风格服务时选择非原图风格，返回明确的「当前不支持风格化」错误。
- 任务结果回传本次实际使用的风格，客户端据此展示；风格对该任务的三张候选同时生效。
- 新增可识别的失败原因：风格化失败、风格化内容不合规。两者都不能产出候选。
- 权益接口一并下发风格族是否可用与可选项；不可用时客户端隐藏风格选择，避免展示必然失败的入口。

**生成流水线**

- 顺序为：解码与摆正 → 风格化（仅非原图）→ 抠主体 → 降采样与色号匹配 → 三候选。风格化在抠主体之前，让风格服务看到完整画面。
- 风格化输出的图片必须再次经过内容安全校验，通过后才进入图纸生成；输入原图的安全校验保持现状。
- 风格化不改变成品尺寸档、色卡档、三候选策略与色号上限；所有既有断言继续成立。

**两级缓存与内容寻址**

- 风格缓存：以「原图内容 + 风格标识 + 模型/提示词版本」为键，命中时不再调用风格服务。
- 图纸缓存：既有内容寻址键扩展为「原图内容 + 成品尺寸档 + 色卡档 + 高级设置 + 风格标识」，换风格必须产生新图纸，不能命中旧风格的图纸。
- 只改成品尺寸档、色卡档或高级设置时，应复用已风格化的图片，不重复调用风格服务。
- 任务复用仍遵守既有归属规则：匿名任务只对匿名请求复用，登录账号各自独立。

**失败与降级**

- 风格服务超时、非成功响应、返回不可解码图片时，任务以「风格化失败」结束，不自动无限重试。
- 客户端在风格化失败时提供两个动作：「重试」与「跳过风格，按原图生成」；跳过风格不需要重新上传或重选图片。
- 风格化结果被内容安全拦截时，以「风格化内容不合规」结束，提示用户换图。
- 未配置风格服务时，原图生成行为与现网完全一致。

**界面**

- 生成页在主流程中增加风格族选择，默认原图；选择结果随生成请求提交。
- 预览页展示本次实际风格；非原图时展示「AI 风格化」标识。
- 风格化失败时展示可重试提示，并提供跳过风格的入口；风格不可用时隐藏选择器。
- 高级设置面板不新增风格相关参数，避免主流程参数膨胀。

**看板与失败样本**

- 生成、首图接受与失败记录都带上风格；看板汇总在既有时间与渠道过滤下，新增按风格的拆分：生成任务数、生成用户数、首图接受数与接受率、风格化失败次数与失败率。
- 同一任务的风格化失败只计一次；成功生成与风格失败的统计口径互不污染。
- 失败样本记录、列表与 CSV 导出增加风格字段；既有列与时间过滤保持不变。
- 原有漏斗、7 日二次生成与盲测统计口径不变；风格维度只是叠加拆分，不改变分母定义。

**合规**

- 用户原图送往第三方风格服务前，需在隐私指引中说明用途、第三方与留存方式。
- 面向公众上线真实生成式服务前，完成生成式 AI 备案与内容标识；本轮假实现不构成真实生成式服务。
- 高清图与打印页上的 AI 标识排版，留到真实厂商上线前补齐；本轮先覆盖预览页标识。

## Testing Decisions

- 只测外部行为，不测实现细节；不做像素级外观断言，风格化效果用人工视觉回归。
- 沿用既有两条 seam：
  1. **云端生成接口**：覆盖风格参数校验、任务结果回传、三候选规则、内容安全与失败原因。断言：默认原图；非法风格报参数错误；非原图风格仍恰好三候选；所有色号仍在所选色卡档；成品尺寸档与拼板数不变；未配置风格服务时原图行为与现网一致；风格化被拦截时不产出候选。
  2. **看板后台接口**：断言按风格拆分后的生成量、接受率、失败次数与失败率，且时间与渠道过滤仍然生效；失败样本列表与 CSV 含风格列。
- 新增一个受控测试替身 seam：注入假风格服务，用它模拟成功、超时、非成功响应、返回坏图四种情况；通过调用记录断言「同图同风格只调用一次」「仅改尺寸或色卡不重复调用」「换风格重新调用」。该替身只在服务端装配层注入，不进入小程序端。
- 先例：既有导出接口与看板接口的 seam 测试形态；沿用真实起 HTTP 服务、注入可控依赖的写法。
- 不写小程序页面自动化；风格选择的界面与跳过流程走人工冒烟。

## Out of Scope

- 真实厂商选型、账号、密钥、签名、计费与供应商重试策略；等凭据到位后单独接入。
- 风格强度滑杆、参考图、自定义提示词、多风格叠加与命名 IP 风格。
- 风格化的单独计费、次数包与配额；本轮不新增付费点。
- 端侧或本地模型推理。
- 高清图与打印页上的 AI 标识排版；真实供应商上线前补齐。
- 风格质量调优与风格盲测；验证期另行执行。
- 已生成图纸的风格二次转换；换风格需重新生成。

## Further Notes

- 成本控制的关键是两级缓存：同一张原图同一种风格只调用一次风格服务；验证期需观察实际调用量与缓存命中率。
- 假实现应确定性输出，便于自动化测试与本地演示；不得在未配置真实服务时被生产流量误用。
- 供应商契约建议：接受原图与风格标识、返回图片二进制与内容类型、支持超时与幂等键；不要只返回外链，服务端需下载并校验图片可解码与尺寸上限。
- 本规格接替现有规格中「风格族第 2 迭代」的占位描述；现有规格的其余决策继续有效。
- 验证期四闸门与盲测执行方式不变；新增的风格拆分只用于判断风格投入优先级。
