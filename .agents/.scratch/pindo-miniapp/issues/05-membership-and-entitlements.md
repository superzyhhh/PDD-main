# 05 — 会员开通与权益

**What to build:** Android 端可用微信支付开通月卡 9.9 元、年卡 69 元；开通后立即解锁无限高清导出与 291 档位；到期后权益收回，但已保存的图纸仍可查看与导出。iOS 端只展示权益，不出现任何购买按钮、价格或虚拟商品文案（ADR-0003）。

**Blocked by:** 04

**Status:** ready-for-human

- [x] Android 端支付完成后会员状态即时生效，无限导出与 291 可用
- [x] iOS 端不出现可触发的购买按钮、价格或虚拟商品文案
- [x] 会员到期后权益收回，已保存图纸仍可查看并按免费额度导出
- [x] 权益以服务端为准，换设备后状态一致
- [x] 支付失败或取消不改变会员状态，不产生脏数据

## Comments

- 服务端新增会员领域：会员卡（月卡 30 天 990 分、年卡 365 天 6900 分）、订单状态（待支付/已支付/已取消/已失败）与按 openId 的会员记录。到期后仍保留记录并标记失效，客户端能说明「权益已收回」而不是丢失状态；有效期内再次开通从当前到期时间续期。
- 新增 `GET /api/membership`：返回会员状态、可购会员卡与价格；iOS 端（请求头 `x-platform: ios`）返回 `purchaseAvailable:false` 且套餐为空，不向端侧下发任何价格。未配置支付渠道时 Android 同样不下发价格。
- 新增 `POST /api/membership/orders`：需登录；iOS 直接 403 `purchase-not-allowed`；未知会员卡 400 `invalid-plan`；支付渠道未配置 503 `payment-unavailable`，订单同时置为失败，不伪造支付成功。
- 新增 `POST /api/membership/notify`：支付渠道回调统一入口。只有校验通过的「支付成功」才授予权益；同一订单重复成功通知不重复延长；取消/失败关闭待支付订单，已取消订单的迟到成功通知不再授予；未知订单 400。未支付订单保留 2 小时后清理，避免脏单无界增长。
- 291 档位改由服务端会员状态判定，运营白名单作为额外放行保留；会员到期后立即回到 403 `advanced-not-allowed`。
- 导出额度改为按请求计算：会员 `limit:null`，不计次、不拒绝；免费账号仍按上海自然日 1 次。出图失败只对实际扣过次的账号归还额度。已保存的导出资源在到期后仍可下载。
- 支付渠道抽成 `PaymentProvider` 边界：`available` 决定客户端是否展示价格与购买入口；未配置时为不可用；本地/测试用沙箱由入口显式注入，生产环境禁止启用 `PAYMENT_SANDBOX`。
- 客户端会员页展示当前状态（免费/会员有效至某日/已到期）、三项权益与会员卡；仅在服务端声明可购买且非 iOS 时渲染价格与「开通」，点击后拉起 `wx.requestPayment`，支付成功短轮询确认权益；iOS 不渲染任何价格或购买入口，且 `buy` 动作在 iOS 进一步拦截。
- 验证：类型检查、GPL 边界检查与 26 个测试全绿，其中会员接口 7 条覆盖 Android 开通生效、iOS 限购、到期收回与已保存资源下载、取消/失败与重复通知、跨设备一致、支付未配置、登录与套餐校验。

## 待配置 / 待人工

- **微信支付商户参数**：真实开通需商户号、API v3 密钥、证书序列号与商户私钥。当前 `PaymentProvider` 只有「未配置」与「沙箱」两种实现，生产必须补微信支付实现后再开放购买；在此之前客户端只展示权益。
- **支付联调**：需在沙箱/真实商户下验证下单、回调验签、重复通知与退款口径，归工单 12 真机冒烟。
- **持久化**：会员记录与订单目前与任务、导出缓存一样保存在进程内存，重启即丢；上线前需落库，并把额度、会员到期判定改为持久层查询。
- **iOS 审核确认**：需人工确认会员页文案与页面结构符合 ADR-0003，不出现价格、购买入口与虚拟商品引导。
