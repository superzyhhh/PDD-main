# 拼豆图纸生成小程序 · 规格

## Problem Statement

零经验的拼豆玩家看到喜欢的图片，想把它变成能照着拼的图纸，但现有工具把失败成本转嫁给了用户：

1. 上传后要自己判断尺寸、色号数量、抖动、背景处理等参数，不懂的人只能乱试。
2. 生成结果经常主体没抠对、颜色糊成一团，用户不知道该怎么修，只能弃用。
3. 工具用的色号超出玩家手上的 MARD 221 套装，为一张图被迫额外采购。
4. 大图在手机上看不清，打印出来没有对齐坐标，拼的时候大面积错位。
5. 先用免费工具试，结果带水印或限次数，真正想拼时才发现要换工具。

结果是：需求真实且高频，但用户对任何一款工具都没有使用习惯，谁把「上传即可用、照着能拼」做扎实，谁才有留存。

## Solution

一个微信小程序：上传一张图，不做任何参数调整，直接拿到 3 张可选的图纸，选一张即可高清导出、分块打印，并按图纸用量看到材料清单。

- **零参数主流程**：用户只做三个可感知选择——成品尺寸档、色卡档、是否需要风格化（本版不做风格化）。
- **三候选**：同一张图一次产出三张图纸（保主体细节 / 保色彩层次 / 保少色号），用户选一张即完成出图。选中第一张计入「首图接受」。
- **失败有出口**：三张都不满意时才出现「换张图」「裁主体」两个动作，失败样本回流。
- **照着能拼**：高清无水印导出、按 A4 分页的分块打印图（带对齐坐标与页码）、色号用量与材料清单。
- **付费点后置在「拼」上**：免费无限预览，每日 1 次高清导出；会员解锁无限导出、291 进阶色卡档与后续风格化次数包。

## User Stories

1. 作为零拼豆经验的新手，我想只上传一张图就能拿到图纸，这样我不用先学一堆参数是什么意思。
2. 作为新手，我想在几秒内看到抠主体是否正确，这样我不会等半天才发现这张图不能用。
3. 作为新手，我想一次拿到三张风格不同的图纸，这样我总有一张能接受，而不是反复重试。
4. 作为新手，我想三张都不满意时被明确告知下一步该做什么，这样我不会卡在同一个错误结果上。
5. 作为新手，我想选择成品尺寸（小/中/大），这样我事先知道自己要买几块板和多少豆。
6. 作为已有 MARD 221 套装的玩家，我想只从 221 色里配色，这样我不需要为一张图额外采购。
7. 作为会员，我想切换到 291 进阶色卡档，这样我能得到更还原的结果。
8. 作为玩家，我想在 221 档位的图纸上被明确提示哪些色号需要额外购买，这样我不会拼到一半才发现缺色。
9. 作为玩家，我想看到图纸的色号清单与每种的数量，这样我能估算材料成本。
10. 作为玩家，我想一键跳转去购买材料清单，这样我不用自己逐个搜色号。
11. 作为玩家，我想导出高清无水印的图纸，这样我打印出来不会糊。
12. 作为玩家，我想把大图按 A4 分页打印，每页带对齐坐标与页码，这样我拼的时候不会错位。
13. 作为玩家，我想看到分块印刷的拼板数量，这样我能提前准备底板。
14. 作为玩家，我想在图纸上看到网格线与色号标注，这样我照着拼时不用来回对照清单。
15. 作为玩家，我想把最近生成的图纸保存在「我的图纸」里，这样我下次能直接找到。
16. 作为玩家，我想从「我的图纸」重新导出一张旧图纸，这样我换设备后仍能打印。
17. 作为玩家，我想删除不想保留的图纸，这样我的列表不会塞满失败的尝试。
18. 作为玩家，我想在图纸超出保存上限时看到明确提示，这样我知道旧图会被清理。
19. 作为新手，我想在「高级设置」里看到被隐藏的参数（抖动、背景处理、色号上限），这样我在少数情况下可以手动干预。
20. 作为新手，我想高级设置默认收起，这样我不会被参数吓退。
21. 作为玩家，我想生成失败时看到可重试的提示而不是报错码，这样我知道是网络问题还是图片问题。
22. 作为玩家，我想在上传的图片不合规时被告知原因，这样我知道该换图而不是反复重试。
23. 作为玩家，我想用微信直接登录，不用注册账号，这样我能马上开始。
24. 作为玩家，我想不登录也能预览，这样我可以先试用再决定是否付费。
25. 作为免费用户，我想每天有 1 次高清导出，这样我能验证效果后再决定是否开会员。
26. 作为免费用户，我想预览不限次数，这样我敢反复试不同图片。
27. 作为付费用户，我想开通会员后立刻解锁无限导出，这样我不用等生效。
28. 作为付费用户，我想看到会员包含哪些权益（无限导出、291 档位、后续风格化次数），这样我知道钱花在哪。
29. 作为付费用户，我想在会员到期后仍能访问已生成的图纸，这样我的作品不会消失。
30. 作为付费用户，我想账号额度以服务端为准，这样我不会因换设备而丢失权益。
31. 作为玩家，我想把图纸以小程序卡片转发给朋友，这样对方能直接打开查看。
32. 作为玩家，我想在弱网下继续操作，这样我不会因为一次超时丢掉已选的候选。
33. 作为玩家，我想同一张图重复生成时不重复计费，这样我不会因为误点而浪费次数。
34. 作为玩家，我想在图纸预览时看到实物色差提示，这样我对成品的颜色差异有预期。
35. 作为玩家，我想在生成大图时知道大致要等多久，这样我不会以为程序卡死。
36. 作为运营者，我想知道有多少人选中了第一张候选，这样我能判断「零失败」是否成立。
37. 作为运营者，我想看到失败样本（三张都不满意）的图片特征，这样我能定向改进算法。
38. 作为运营者，我想看到从生成到付费的漏斗，这样我能判断付费点是否有效。

## Implementation Decisions

**形态与部署**

- 原生微信小程序；服务端为微信云托管容器（Node 常驻进程），不使用云函数承载图像处理，也不引入跨端框架。
- Pindo 的 GPL 引擎整包部署在云端容器内运行，小程序端代码包内不含任何 GPL 覆盖代码（ADR-0001）。引擎中依赖浏览器对象的图片解码与图案识别两处，以 Node 侧实现替换。
- 出图为异步任务：提交 → 轮询/订阅结果 → 回传三候选。客户端不做重算法。

**端云切分**

- 端侧只做低精度预览（成品尺寸档对应的 20—50 格级别），仅用于「主体是否抠对」的即时确认；预览用小程序原生 canvas 渲染。
- 上传原图后云端完成精算；高清导出与分块打印图的渲染也在云端完成并缓存，端侧只负责展示与保存。

**生成接口契约**

- 提交：原图引用、成品尺寸档、色卡档 → 任务标识。
- 查询：任务标识 → 状态（排队/处理中/完成/失败及失败原因）+ 三候选，每个候选含格网尺寸、色号矩阵引用、色号用量统计、预览图引用。
- 导出：图纸标识 + 导出类型（高清整图 / A4 分块）→ 可下载资源引用；同一图纸同类型导出结果复用缓存。
- 同一张原图 + 同一参数组合生成结果确定（按内容寻址缓存），重复提交不新增扣费。

**三候选策略**

- 三套自动策略由既有引擎参数组合而成：保主体细节（边缘感知降采样、开启抖动、色号上限放开到档位上限）、保色彩层次（平均降采样、开启抖动、限制中等色号数）、保少色号（平均降采样、关闭抖动、色号数压到低值）。
- 候选顺序固定：第一张为「保主体细节」。用户选中第一张计入「首图接受」，该判定只由用户的选择动作触发。

**成品尺寸与色卡**

- 成品尺寸档：小 29×29（1 块板）、中 58×58（4 块板）、大 87×87（9 块板）；拼板规格统一按 29 格。
- 色卡档：基础 221、进阶 291（仅会员）。所有色号必须落在该档色卡内；221 档图纸命中 221 之外的色号视为缺陷。
- 出图时展示实物色差提示；291 档图纸需明确标注「超出 221 套装，需额外采购」。
- 色卡数据来源按 ADR-0002 处理，产品内不宣称「官方色卡」。

**主流程交互**

- 用户可见选择仅三项：成品尺寸档、色卡档、风格族（本版不出现）。抖动、背景处理、色号上限、降采样模式、系列色过滤全部自动，收进默认折叠的「高级设置」。
- 三候选不满意时出现「换张图」「裁主体」两个动作，并记录失败样本。
- 免费额度：预览不限次；高清导出每日 1 次；额度与会员状态一律以服务端为准，客户端不做可信判断。
- 会员：9.9 元/月、69 元/年；权益为无限高清导出、291 档位、后续风格化次数包（本版不发放）。iOS 端不提供购买入口，仅展示权益（ADR-0003）。

**数据与内容**

- 登录：微信静默登录获取标识，不强制手机号；未登录可预览，导出与保存需登录。
- 「我的图纸」云端保存最近 50 张，超出淘汰最旧并提示；删除为即时生效。
- 上传即调用微信内容安全接口，命中则阻断任务并留痕，向用户给出可换图的原因提示。
- 材料清单展示色号、数量与预估包数，并提供「去购买」跳转；不接佣金、不做下单。

**合规**

- 本版不含风格化，不接入任何生成式模型，因此不涉及生成式 AI 备案与内容标识。
- 小程序类目报「工具—图片处理」；用户协议明确上传内容权属由用户担责。

## Testing Decisions

- 只测外部行为，不测实现细节；不写依赖内部函数调用顺序的测试；不做像素级外观断言（改为人工视觉回归）。
- 已确认两条 seam：
  1. **云端生成接口**（最高 seam，覆盖抠图、减色、色号匹配的整条流水线）——断言：每次返回恰好 3 个候选；候选顺序固定；同图同参数结果确定；每候选所有色号均属于该档色卡；候选色号数不超过档位上限；格网尺寸与成品尺寸档一致；原图存在主体时候选不是全空；三候选至少在色号数或降采样策略上互不相同；内容安全命中时不产出候选并返回可识别的阻断原因。
  2. **分块导出纯函数**（本项目唯一新增确定性 seam）——断言：分页覆盖全图且不重不漏；每页格数不超过 A4 在目标 DPI 下的上限；每页对齐坐标与页码正确；拼板数与成品尺寸档一致。
- 不测小程序页面自动化（成本高、稳定性差），关键路径用人工冒烟：上传 → 选图 → 导出 → 保存。
- 不测微信支付流程本身，使用沙箱手工验证会员开通与额度变更。
- 先例：Pindo 引擎已有基于 vitest 的纯函数规格（降采样、色号数限制、图案清理、主体裁剪），云端生成接口与分块导出沿用同样的测试形态。

## Out of Scope

- 风格化与风格族（动漫风、Q 版、像素风、写实风、线条风）——第 2 迭代，且需接入已备案第三方生成式 API 并加 AI 生成标识。
- 材料包下单、佣金结算、自营供应链与履约。
- 公共图纸广场、社区、推荐流。
- 分享海报生成（本版仅用小程序原生转发）。
- B 端门店工具（另出方案文档）。
- 多品牌色卡、291 以外的色卡档位。
- 逐行打卡、进度保存等拼装辅助。
- 命名式 IP 专属优化与任何 IP 图库。

## Further Notes

- 验证期（2—4 周、小红书 + 抖音垂类投放、300—500 名完成一次生成的真实用户）四闸门全过才扩功能：盲测相互胜率 ≥60%、首图接受率 ≥70%、生成→付费转化 ≥5%、7 日内二次生成 ≥25% 且 ≥20 人主动购买某个具体功能。盲测执行：20 名零经验用户、5 组、单问「哪张你更愿意直接照着拼」。
- 每单生成 3 个候选意味着约 3 倍算力，缓存与内容寻址是成本控制的关键；上线前需按真实图片尺寸压测云端内存与超时。
- 色卡数据（221 与 291）来源与授权未确认，是上线前必须关掉的法务敞口（ADR-0002）。
- GPL 边界须在 CI 中显式检查：小程序端产物不得包含引擎源码或编译产物（ADR-0001）。
- B 端轻量工具方案、风格化供应商选型与次数包定价，均在对应阶段单独立项，不阻塞本版。
