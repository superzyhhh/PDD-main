**What to build:** 看板把「风格化失败率」改成口径明确的「风格转换失败率」，免费风格的内部失败与高级风格的外部依赖失败都算进去，内容不合规不算；其余统计口径与失败样本能力保持不变。

**Blocked by:** 06

**Status:** ready-for-human

- [x] 看板按风格返回「风格转换失败次数与失败率」，接口字段与文案不再使用「风格化失败率」
- [x] 免费风格的内部失败与高级风格的外部依赖失败都计入，同一任务只计一次
- [x] 风格化内容不合规不计入转换失败次数
- [x] 失败样本记录、列表与 CSV 保留风格字段，既有列与时间过滤不变
- [x] 原有漏斗、7 日二次生成与盲测统计口径不变
- [x] 自动化测试覆盖新语义、去重、时间与渠道过滤叠加

## Comments

**改名范围**：看板按风格的字段 `styleFailure` → `styleConversionFailure`，内部数组与方法同步改为 `styleConversionFailures` / `recordStyleConversionFailure`，服务端失败文案改为「风格转换失败，请重试」「风格转换结果不符合内容规范，请换一张图」。保留不变的有两处：任务失败码 `style-failed`（小程序按码判定并展示重试/跳过）与日志事件 `style_failed`（既有个案留存按此检索），二者只作机器标识，不属于看板文案。

**计入口径**：风格转换失败事件在 `failStyleConversion` 一处统一上报，免费风格的本地算法抛错与高级风格的外部依赖失败走同一条路径；`recordOnce` 按任务去重；风格化结果被内容安全拦截走 `style-blocked`，不调用失败上报。失败率分母为该风格生成任务数加失败数。

**装配层修正**：为验证「免费风格内部失败也计入」，服务端新增可选注入 `freeStyle`（缺省仍是本地算法），与 moderation / payment / style / now 的注入约定一致；生产入口不注入，始终走本地算法。

**测试**：新增免费风格失败用例——第一次调用抛错计入 `flat`（`count:1`、`rate:1`），同风格在另一渠道成功出图后该渠道仍为 `count:0`、生成任务 1，且失败时间落在窗口外时不计入，把「新语义 + 去重 + 时间与渠道过滤叠加」串在一条用例里。内容不合规不计入、失败样本与 CSV 风格字段、漏斗与留存口径沿用既有用例，字段改名后全部通过。

**遗留人工项**：看板为内部接口，无独立前端页面；真机与真实看板联调归工单 12。
